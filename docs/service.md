# 盲测服务

`service.py` 在交换资料(见 [交换约定](exchange.md))上提供公布申请、访问结果与候补评审。评估时点 `at` 是 URL 编码后的带偏移时间, 缺省取当前时刻。只采纳该时点已到达的记录: 实测版本 `created`、预测 `entered`、申请 `submitted`、回执 `arrived` 均须不晚于 `at`; 回执的业务效力自 `happened` 起算, 到达时间不代替业务时间。

执行 `python3 service.py` 后, 回环地址 8088 端口可用, `GET /health` 返回服务状态。

## 公布申请

### `GET /v1/publications?suite=...&at=...`

套组公布状态(保管方与评审视角)。轮次封闭前一律暂缓; 封闭后逐组给出可公布的实测版本(含 `supersedes` 更正链, 两版都可追溯)或暂缓原因。某组可公开的前提是涉及该组的所有轮次均不再接受预测; 与未封闭轮次同组的实测值及可反推差值暂缓公布。`requests` 列出已收到的公布申请回执。

### `POST /v1/publications`

申请方请求查看自己的比较明细, 正文 `{"team": "...", "suite": "...", "at": "..."}`(`at` 可省)。仅受邀且未退出的团队可查: 未受邀或已退出返回 `403`, 轮次未封闭返回 `409`。暂缓组别只给原因, 不给出实测值、误差或合格结论(`verdict` 为 `null`), 避免可反推的差值泄漏给仍可提交新预测的团队。

## 访问结果

### `GET /v1/results?team=...&at=...`

申请方视图, 分三类:

* `comparisons`: 已可查看的比较(逐组的预测、实测、误差与是否计入盲测证据);
* `opportunities`: 批准的中试机会(已确认、复查中、可递补);
* `waiting`: 仍在等待的项目及其原因(未封闭的轮次、暂缓公布的组别、候补中的申请)。

已退出团队的实测明细不再提供, 只保留状态说明。

## 候补过程

### `GET /v1/pools?at=...` / `GET /v1/pools/{pool}?at=...`

席位池候补过程, 供评审核对每个席位的证据和占用人。候补按合格候补登记时刻排序, 同刻按申请号。已确认席位因实测更正失去关键套组时进入 `review`(复查), 席位仍被占用, 不再许给别家; 未被认领的席位按当时仍满足约定的候补递补(`promotable`)。已占用正式邀请的成员不能用同一套组在另一个组合同时占位(`blocked`)。证据条目中的 `re_evaluate` 与 `qualification_changed` 标出更正后需重评的候选, 其余获准继续作为盲测证据。

### `GET /v1/applications/{id}?at=...`

单个申请的证据核对: 有效成员与已退出成员、支撑套组、锁定的预测版本(截止后送达的不得更换, 列入 `rejected`)、更正前后的合格变化。该时点尚未提交的申请返回 `404`。

## 示例

```
curl 'http://127.0.0.1:8088/v1/pools/CAP-P?at=2027-01-18T11%3A30%3A00%2B08%3A00'
curl -X POST http://127.0.0.1:8088/v1/publications \
  -d '{"team": "QING", "suite": "R-1", "at": "2027-01-18T11:30:00+08:00"}'
```
